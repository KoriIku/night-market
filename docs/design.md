# 夜市一百块 · 设计备忘

## 一句话

一条能走进去的夜市：口袋里的 100 块不被"花掉"，而是被一串"都不算数"的小数字安安静静地碎掉。

## 核心体验

爽 → 无感 → 累计 → 惊醒 → 复盘。
游戏卖的不是购物，是结账那三秒的"哦豁"。

## 已确定的方向（v0.1）

- 纯体验，不做关卡化玩法包装；场景就是夜市，主角就是玩家。
- 网页轻量小游戏，只用 Three.js（无物理引擎、无 UI 框架）。
- 3D 建模 + 倾斜俯视/斜 45 度视角，微缩模型观感：整个街区搭在一块方形底座上，可自由拖拽旋转与缩放。
- 100 元是心理参照而不是消费上限：全程不显示余额数字，也不提供钱包入口，购买不会因金额不足被拦截。
- 招牌机制：**猜花销**（随时可猜、离开时最后猜一次，误差决定复盘称号）。
- 价格陷阱：用“10 元起”“3 元/串起”“8.8 元/两”等低价锚点吸引，再通过大小份、加料、起卖量和称重抬高实付。
- 烤冷面、冰粉、柠檬茶把基础款放在最前，再按价格从低到高单列加料和升级费用；套餐总价不再占据菜单首屏。
- 价格以真实小吃摊常见的 10/15/20 元为主，混用不同尾数，避免机械地全部取整或集中在 .8/.9。
- 一次普通逛吃大约 5-6 次购买就会接近或超过 100 元；示例路径为 19.5 + 22.5 + 18.8 + 28.6 + 9.9 = 99.3 元。
- 每个摊位前有独立点单圆环；从圈外点击会走到圆环内侧并自动打开菜单，已经在圈内时点击则立即打开。`E` 键和浮动“点单”按钮作为备用入口。
- 满减/会员价留给第二关（1000 元档，商场），不放进夜市第一关。
- 购买不设金额上限，结算只统计累计花销和猜价误差。

## 关卡

1. 夜市 · 100 元：10 个摊，5 对面对面，走完整条街 3-6 分钟。
2. 商场 · 1000 元（未做）：冷白灯、扫码、会员价、满减、停车费补刀，与夜市形成"有痛感 / 无痛感"的对照。

## 美术方向（当前执行中）

- 三渲二：三段式卡通渐变 + 暖色受光 + 冷色阴影 + 轮廓光。
- 描边：反壳（inverted hull）做法，整条街一次 draw call。
- 夜景但要亮：灯串、灯笼、招牌、摊位灯泡、窗光、地面暖光池，共同把画面点亮。
- 材质干净、轮廓明确、色彩柔和；暖光为主，霓虹作点缀。
- 微缩模型气质：方形底座 + 边缘装饰线；场景是**开放的小吃街**，不做围合建筑、不做屋顶。
- **俯视不遮挡铁律**：街道上空与沿街 6 米内不放高于 2.2 米的实体，不出现屋顶、墙面、大箱体；灯串、招牌、旗帜都用细杆与小体量；任何新模型都要先过一遍俯视视线检查。
- 动效（部分已做）：蒸汽与油花、灯笼与灯串微闪、镜头上平滑跟随；待做：招牌摆动、风铃、偶尔经过的自行车。

## 待定

- 主角是否需要更多动作（吃、递钱特写）。
- 是否加入 NPC 群众（目前只有几个静态剪影）。
- 音效：目前是程序化合成（噪声底噪 + 摊前滋滋声 + 硬币音），后续可换成实录。
